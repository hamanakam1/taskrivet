# Contributor instructions

Read README.md and SECURITY.md before changing behavior. Keep all fixtures synthetic.
Run `python3 -m unittest discover -s tests -v` before proposing a change.
Do not conflate eligible routing with authorization, a finished session with accepted
work, declared usage with measured billing, or ledger checks with process isolation.
Stage only the paths you own. Never add provider credentials or private transcripts.
Keep private deployment names, internal architecture, operational screenshots, local
installation paths, and real ticket data out of public source, docs, and issues.
Use generic integration names, explicitly configured origins, and synthetic fixtures.
