IMPLEMENTED RECOVERY

Reconcile before another attempt.

A recorded failure, expired lease, exhausted reported budget, or three identical checkpoint evidence entries blocks ledger progress. The operator reconciles the worker and records a reason before retry. Retry returns the task to Ready; it preserves failure history and cumulative reported usage. Starting again still checks the remaining budget and resource ownership.

PLANNED AUTOMATION

Recover intelligently within limits.

The intended executor will classify the blocker, use bounded recovery attempts, change tools or approach when justified, and work on another eligible ticket when progress is unavailable. Scoped authority, verification, and source-owned acceptance must be enforced before this becomes autonomous behavior.

This is the local ledger lifecycle, not proof of external ticket completion. Finish requires a checkpoint and evidence; an explicit acceptance decision is separate. Cancellation is also supported from Ready, Blocked, and Review—the map shows the latter two paths. A blocked or cancelled ledger record does not itself terminate a process.

From a ticket to a traceable result.

IMPLEMENTED FOUNDATION

Start with the source of truth.

The optional ticket preview reads a bounded page from an explicitly configured local ticket service. It shows source state, readiness, and known holds. Taskrivet also has its own local coordination ledger.

Reading a ticket does not claim it or authorize execution. Automatic ticket selection and atomic source claims remain planned.

04 / Connections with boundaries

Activity becomes a record, not a command.

INBOUND OBSERVATIONS

Notice changes.

Observe issues, comments, pull requests, review comments, commits, workflow runs, releases, and repository events. Deduplicate repeated observations and retain changed revisions.

SOURCE RECONCILIATION

Keep the ticket informed.

A private adapter can write a repository activity digest into an explicitly mapped existing ticket. Revision checks and independent readback preserve source ownership and expose conflicts.

EXPLICIT PUBLICATION

Share deliberate summaries.

An outbox binds a selected public summary to an issue and publication key. It checks the author and exact content, verifies delivery, and avoids blind retries after an uncertain send.

Polling is bounded and can miss activity. Suggested response categories guide review; they do not automatically execute contributions, merge changes, create tickets, or mark work Done. Full per-issue lifecycle synchronization and webhook delivery remain planned.

05 / A truthful status

What works today. What comes next.

AVAILABLE IN THE ALPHA
  • Embedded terminals with a standalone local session service.
  • Session reconnection after desktop quit; service failure or reboot is not recoverable.
  • Tool discovery across installed executables, with 26 coding-agent command-name profiles.
  • Bounded context, checkpoints, resource claims, and recurring-failure records.
  • GitHub receipts and review categories, plus optional app-open polling and a private ticket adapter.
PLANNED / NOT YET PROVEN
  • Automatic execution of eligible tickets with qualified tools and scoped access.
  • Measured routing based on actual quality, latency, entitlement, and cost.
  • Complete activity handling using webhooks and source-specific reconciliation.
  • Verified automatic acceptance and intelligent bounded recovery.
  • Signed desktop distribution and live outbound issue-delivery qualification; the release run encountered GitHub content-creation throttling.
